# RPG-системы: реализация (этап 1)

Нормативный источник — `docs/gdd/RPG_AI_Implementation_Package.md` (GDD v1.2, решения D001–D214).
Здесь — как правила легли на проект, выбранные технические параметры и что осталось.

## Как открыть

- `npm run dev`, затем в главном меню — «Тестовая площадка». Обычная игра («Продолжить игру»,
  «Создать персонажа», мир «Дикие земли» 2000 × 2000) и её сохранение не изменились.
- Режим разработки: `http://localhost:5173/?dev=1` — панель справа (ресурсы, оглушение,
  замедление, телепорты к столбам и пруду) и объект `window.rpg2` для автоматических проверок.
  Без `?dev=1` панели и команд нет (D214).
- Проверки: `npm test` (файл этапа — `tools/tests/rpg2.ts`).

## Технические параметры (выбраны по проекту)

| Параметр | Значение | Почему |
|---|---|---|
| Масштаб | 1 блок = 1 м | В проекте клетка = 1 единица мира, герой ~1,8 блока |
| Гравитация | 19,53 м/с² | Подъём 1 м за 0,32 с (`JUMP2.height`, `apexTime`) |
| Скорость отрыва прыжка | 6,25 м/с | √(2gh) при h = 1 м; второй прыжок заменяет вертикальную скорость тем же импульсом |
| Коллизия героя | столб, радиус 0,32 м, высота 1,8 м | Радиус прежнего героя; опора — 5 точек следа (радиус × 0,7) |
| Ступень | до 0,3 м — шагом; выше — прыжком | D212; в блоках: ступени 1/4 блока проходятся, 1/2 и выше — прыжком |
| Наклон опоры | ≤ 45° | Верх блока плоский (0°) — опора; бок блока (90°) — стена |
| Допуск края в воздухе | 0,03 м | Ноги на высоте верха блока считаются над ним (прыжок 1 м достаёт блок 1 м) |
| Управление в воздухе | разгон 8 1/с, предел max(скорость отрыва, 2,5 м/с) | D193/D212 |
| Наземный разгон | 30 1/с | Как у прежнего героя |
| Плавание | глубже 1,2 м; ноги на 1,1 м ниже поверхности | Технический выбор; выход на берег — верх ≤ поверхность + 0,3 м |
| Уклонение | 6 м/с × 0,5 с = 3 м | D167/D170; замедление фиксируется при запуске |
| Шаг симуляции | ≤ 1/60 с, кадр ≤ 0,05 с | Таймеры дробные, деление тика точно по моменту выхода из боя и окончания задержки ST |
| Мышь | 0,0028 рад/пикс по горизонтали, 0,0018 по вертикали × чувствительность | Камера та же (`CameraRig`): круг по горизонтали, наклон 25–50°, не уходит в землю |
| Автосохранение | каждые 600 с активного времени | D041 |
| Часы | 0,4 игровой минуты на секунду активной игры | D079 |

## Управление тестовой сцены

Основная игра остаётся только на мыши (правило владельца в `CLAUDE.md`). На тестовой площадке —
клавиатура и мышь по D211: W/A/S/D относительно камеры, мышь — обзор (курсор захватывается
щелчком; если браузер не даёт захват — обзор при зажатой ПКМ), ЛКМ — атака, Space — прыжок и
воздушный прыжок, Shift — уклонение, удержание Ctrl — спринт, Caps Lock — ходьба/бег, I —
инвентарь, M — карта, C — персонаж, F5/F9 — быстрое сохранение/загрузка, Esc — закрыть верхнее
окно или пауза. Корпус героя смотрит по направлению камеры (иначе «назад относительно корпуса»
в D183/D170 не имел бы смысла). Все клавиши переназначаются в «Пауза → Управление»; при конфликте
спрашивается замена; есть «По умолчанию». Хранение — `localStorage["cubeborn.controls"]`, отдельно
от прохождений.

## Сохранение

- Основное сохранение (`cubeborn.save.v1`, версия 8) не менялось — версия не поднималась.
- Тестовое прохождение: `cubeborn.rpg2.test`, формат `cubeborn.rpg2.playthrough`, версия 1.
  Хранит характеристики, развитие, HP/MP/ST, задержку ST, таймер боя, позицию и состояние
  движения (воздух, использованный воздушный прыжок, наивысшую точку падения, уклонение, откат,
  оглушение, замедление, ходьбу), день и время, активное время и остаток до автосохранения.
- Запись: сначала во временный ключ, проверка чтением, прежняя запись — в `.prev`; сбой не
  уничтожает рабочий снимок. Старая версия формата переводится с копией `.backup.v<N>`, более
  новая — отказ с понятной причиной. Мёртвый герой не сохраняется.
- Полная система слотов (D040–D047: ручные, быстрые ×3, автоочереди) — этап 6; эта запись станет
  телом снимка.

## Открытые вопросы

1. **Ступени 0,3 м и блочный рельеф.** В основной игре полблока (0,5 м) проходится шагом
   (`CLAUDE.md`), а D212 разрешает шагом только 0,3 м. На тестовой площадке действует D212:
   ступень 1/4 блока проходится, 1/2 — прыжком. Вне ровных мест старой поляны это заметно
   (склоны из полублоков). Рекомендация: оставить D212; если владелец захочет прежнюю лёгкость,
   поднять `SUPPORT.step` до 0,5 одной строкой.
2. **Ctrl как спринт в браузере.** Ctrl+W/Ctrl+T/Ctrl+N браузер не отдаёт странице (закрытие
   вкладки при спринте вперёд на W). В полноэкранном режиме можно запросить Keyboard Lock, но это
   не везде работает. Рекомендация: оставить Ctrl по GDD и предупредить в окне управления, либо
   назначить по умолчанию другую клавишу (например, Л-Alt) — нужен ответ владельца.
3. **Caps Lock** на macOS приходит как нажатие/отпускание переключателя; обработано (keyup тоже
   переключает на macOS), но стоит проверить на реальной машине.
4. **Корпус и камера.** Корпус всегда смотрит по камере (стрейф). Это делает D183 и «назад
   относительно корпуса» однозначными; если нужен поворот корпуса по движению — это изменит смысл
   «назад».
